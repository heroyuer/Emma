# Emma and Emma Dashboard

Emma client → the learner's own Google Drive connection → newly configured family archive root → parent-owned local Drive importer/cache → Emma Dashboard.

The client package contains coaching workflow, portrait, standard Drive dependency and archive helper. No custom server, database or Sites App binding. Real clock checks use actual available host time; unavailable timing is marked unknown. File generation/upload/readback and Voice delegation depend on the intended host.

Archives use schema_version 1 with stable learner_id/session_id, actor_kind learner or parent_test, first name, timestamps/timezone, plugin/rules versions, transcript coverage, exact entries, grounded summary/materials and explicit count definitions. Learner/session identity is configured independently of display name. Suggested layout: root/learners/<learner-id>/sessions/<YYYY-MM>/ and root/parent-tests/<tester-id>/sessions/<YYYY-MM>/. Filename stems retain readable local date/first name/session ID; retries keep that identity. Parent-test archives do not enter child progress analytics. Folder names are not authorization.

The primary machine-readable summary JSON includes actual entries; readable Markdown is optional for importer compatibility but generated by the helper. Publish a receipt last with schema/session/learner IDs, exact folder_id, archive_status verified, verified_at and files [{kind: summary_json|transcript_markdown|summary_markdown, id, name, sha256, mime_type}]. Content hash is SHA-256 of fetched bytes. Do not mark verified unless files and receipt are fetched/read back from the actual configured folder. A forged receipt is not proof of identity/mastery; parent review remains necessary.

Emma Dashboard is a separate local-only repository with a read-only view, local SQLite cache and bounded Drive import. A standalone process needs its own parent OAuth/token integration; it cannot reuse ChatGPT's internal connector credentials. Scheduled import runs on the parent's laptop when awake after authentication/timing setup. Preserve useful journal/report pages from the original as design/reference; no cloud data migration or deletion occurs implicitly.

Parent can push teaching changes through versioned approved packages. Optional runtime central instruction file must be explicitly configured and read on lesson start; inaccessible refresh is reported, never presumed latest. Source packages and active parent instructions are versioned independently. No personal Drive IDs are embedded in defaults.
