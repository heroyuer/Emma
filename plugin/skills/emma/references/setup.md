# Per-account setup and limits

Runtime settings are provided explicitly in the child's own chat/file, never committed to this repository: preferred first name, a unique configured learner folder label, newly designated Drive folder ID, optional current instruction file ID/revision, timezone America/Chicago, and any active session metadata. A first name is not a security boundary. Shared family folders may expose sibling archives to all members; use separately permissioned learner folders if that privacy is required. Do not assert sibling isolation unless Drive permissions establish it.

The package declares the standard Google Drive app ID observed in the installed official Drive package. Each account must be eligible, connect its own Google account and have actual write access to the selected folder. The dependency declaration does not authenticate users or unlock unavailable tools.

Before relying on saving: inspect available Drive tool schemas; verify account identity through a supported identity surface, verify target folder metadata and permissions, then perform an explicitly authorized synthetic upload/readback test. An unavailable account identity surface requires the user to identify the connected account before writes. Upload plain Markdown and JSON as files; Google Docs conversion is not required. Observe actual upload IDs/URLs, then fetch content and folder metadata. If the host cannot generate files or upload/read them, automatic archiving is unavailable. Do not promise it based on search-only access.

Cloud account-owned package creation: in each child's own account, use Plugin Creator when available with the private package archive. Ask to create Emma as a private independent coaching plugin, preserve packaged files and standard Drive dependency, and create no Site/custom server. Inspect its returned package/skill/dependency and install/connect in a fresh chat. General plugin authoring is documented; availability of this specific archive/dependency flow is not verified on either child's free/teen account. If Plugin Creator is absent/restricted, stop that installation path and report it.

Local marketplaces are documented for Work/Codex desktop authoring. They do not establish ordinary native Voice eligibility. Do not silently substitute Codex for the requested ChatGPT experience. Account-owned copies have separate IDs/releases; GitHub pushes do not update them automatically. Update each via its owner-account guarded Plugin Creator update, then inspect version/skill readback and start a fresh chat. Test updates on one account before the other.

Do not create a parent's automation as a learner reminder. Only offer reminders where supported in the learner's own account, after their choice (8 PM America/Chicago, custom, or none), and verify an actual saved task. Reminders do not open Voice or start a lesson clock.
