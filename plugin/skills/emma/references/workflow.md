# Tracked workflow and save queue (0.2.2)

Use `node <installed-skill>/scripts/workflow.mjs command.json` through the available execution tool. The child's only spoken cue can remain Hi Emma; the agent supplies commands. Execution and native Voice delegation must actually be available. The controller does not call Google Drive or capture audio.

## Startup and available turns

`{"action":"start","event_id":"<unique invocation>"}` reads the configured own profile, starts/resumes its actual ledger and returns session ID, clock, local history source and archive readiness. A name may be supplied once if the profile lacks it. `tracked_local_ready` confirms local tracking only; remote saving is separately unverified until an actual write/readback. Read optional current parent instructions and authorized own Drive summaries when available; report the actual revision/history source, never pretend a refresh. `diagnostics` returns concise local status without transcript or credentials.

Use the returned session ID for every `turn`, `stop`, `pause` and `end`. A delayed/wrong-session handoff must not mutate a different current session. `turn` accepts only actual supplied `entries:[{role:"learner"|"coach",text:"…"}]` and optional learner_text/previous_move for advisory next-step guidance. Do not record future generated Voice as already heard. Reading/silence counts until an explicit pause. Topic changes should advance the discussion, not create more echo drills.

## A clear stop is a save request

Call `stop` immediately with stable event_id/session_id. Before25 practice minutes it pauses; at25+ it closes. Explicit permanent finish uses `end` at any time. At30 the next delegated turn suggests wrapping up. No routine early-stop offers or extra exercise after stopping.

Include actual unlogged tail entries, or `final_entries` only for an actual complete labelled prefix supplied by the host. The exact closing request is fsynced before whole-workflow locking. Same event/content retries are idempotent; changed content is retained as separate pending evidence. A busy workflow still retains the payload. Missing startup/profile does not cause fake historical session creation. Unknown/partial capture remains unknown/partial.

The controller records close time, prepares immutable local revisions and returns job_path/session_id/archive_revision/save_state/artifact paths. Pending content and job metadata live outside the plugin under the own profile's runtime/save-queue. A save guard remains even after the clock closes, preventing upgrades from dropping pending work. `retry` with session_id/archive_revision reuses existing exact prepared bytes. If preparation was blocked by bad summary references, explicitly repair summary on retry; original supplied content stays retained. Old queued artifacts are not regenerated by a different generator version. New-day startup preserves prior partial work/queue and starts a fresh Chicago-date session.

## Host-owned Drive stages

1. Verify the actual connected account and configured destination with available Drive tools. A folder/name/role claim is not authorization. Missing tools/destination stays pending.
2. Use returned prepared files. Search stable session filenames; compare/update the actual same-session IDs on higher revision. Never overwrite a different session, create duplicates on retries, change sharing, or send sibling records. Upload/read back exact content and metadata through authenticated tools. Materialize those readbacks separately from upload source files.
3. Call `prepare_receipt` with job session/revision, observed verified_at and all three `readbacks:[{kind,id,name,mime_type,parents,readback_path}]`. Names/MIME must match the prepared artifacts. This produces receipt_path/receipt_name and save_state receipt_prepared_upload_pending; it is still not saved.
4. Upload the named receipt, read it and its actual parent metadata back, then `confirm_receipt` with job session/revision, actual receipt_id, name, parents and separately materialized readback_path. Only archive_verified:true permits the saved claim. A mismatch throws and leaves the pending queue guarded. The controller validates supplied authenticated readbacks; it does not independently fetch remote bytes.

If the host never delegates the stop or supplies the words, this controller cannot run or recover missing speech. Explain the limitation. A saved receipt proves submitted file consistency, not complete Voice capture or learning mastery. Do not label a child session parent_test unless the configured profile is intentionally a parent test.

0.2.1 final handoff: use capture_final with the exact confirmed session_id and strictly prefix-extending final_entries for a later transcript tail after pause/close. It never resumes a stopped clock or teaching, preserves original practice/end timing and creates a higher archive revision. Already recorded full content is idempotent; a mismatched/old session remains pending separately.

## Host evidence and archive quality

At start, optional capability_report contains host_surface (native_voice/text/unknown), instruction_loaded (boolean from actually loading the skill), and transcript_delivery (both_speakers/learner_only/coach_only/unknown). These are sanitized host reports pinned in the session, not independent verification. Diagnostics exposes host evidence and current capture warnings. Absence stays unknown. Test actual Voice separately.

Turn steering uses recent actual coach text to detect repeated echo prompts and requests content progression. Do not pre-log generated responses; supply only delivered text available on a later handoff. Preserve the exact existing prefix for capture_final; missing replies cannot be inserted into old immutable revisions by reconstruction.

Closing jobs return quality independently of archive_verified. Missing/partial summaries and suspicious speaker gaps never discard or block preservation. Supply the required summary fields from actual evidence; explicitly mark unknown learning as unassessed. A retry reuses immutable prepared bytes, so do not claim it repairs an already prepared summary. Use amend_summary with the confirmed session_id, a fresh stable event_id and a nonempty evidence-based summary to create a higher revision for the same paused/closed session, even when no new words arrive. Supply no entries/final_entries. Original artifacts, transcript, clock and end time remain unchanged; retry that exact event after failure. Limited capture suppresses learner word-share ratios. Raw entry counts describe only supplied text.
