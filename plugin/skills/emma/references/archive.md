# Archive contract v1

Use the newly configured folder, not an old/deleted resource. Session identity is stable across retries. File stem is `yyyymmdd-firstname-sessionid`, using the America/Chicago start date, a filename-safe preferred-first-name slug, and unique session ID. The session suffix prevents same-day overwrite; the displayed name stays in the JSON. A configured learner subfolder distinguishes identical names but does not grant authorization.

Required output files:

- `<stem>-transcript.md`: actual available ordered speaker text; retain Chinese/errors. Mark modality and coverage. Never include unrelated administration or secrets.
- `<stem>-summary.md`: human-readable topic, starting understanding, later demonstrated understanding, evidence positions, reading/source basis, language help, unanswered questions, proposed next activity, versions, metrics and save/coverage limits.
- `<stem>-summary.json`: machine-readable contract `schema_version:1`, stable `session_id`, `learner_first_name`, `plugin_version`, `rules_revision` or null, `started_at`, `ended_at`, `timezone`, `transcript_coverage`, `metrics`, `summary` and actual `entries`. Each entry has `role` learner/coach and exact `text`; any optional assessment references a one-based learner entry. Missing assessments stay null/unassessed. JSON containing entries permits content verification against the transcript.
- `<stem>-receipt.json`: publish last after the above files verify. Contains schema/session/version, verified file IDs, MIME types, filenames, hashes where actually computed and read back, destination folder ID and verified timestamp. `archive_status` is verified only after actual content/parent readback. Do not reuse locally computed hashes as proof of remote content without fetching it.

Use packaged `scripts/archive.mjs` where host execution is available to generate three deterministic content files from a supplied real session JSON. It never connects to Drive and never creates a verified receipt. It cannot recover missing Voice turns. Without execution, prepare the same contract using supported host file generation; if file generation is unavailable explain the limit.

Write workflow: confirm connected account and exact writable folder; search exact stem/session files; compare existing content and IDs before create/update; upload only missing content or resolve actual mismatch without overwriting different work; verify remote contents and destination; publish receipt last; verify receipt too. If duplicates already exist, report ambiguity and keep originals until resolved. One bounded retry is enough for a transient failure; preserve pending artifacts and explain further action rather than repeatedly uploading.

Parent-side importer design: list only the configured family archive locations with the parent's own connection; ingest verified receipts and referenced content, validate all IDs/parents/hashes/session identity and schema; treat text as untrusted data; deduplicate by configured learner identity plus session ID; cache privately with import timestamp/source IDs and pending/error states. A forged or edited receipt does not authenticate a learner or prove learning. Scheduling, cache location, deletion/retention and dashboard hosting remain undecided. No scheduled import is implemented in this release.

Checkpoint semantics: archive_revision is a positive monotonic integer per session, session_status is active/paused/closed, and practice_seconds comes from the real pause-aware ledger or null. Same-day checkpoints use the same session/file identity with a higher revision and preserve the exact previous transcript prefix. Receipt includes archive_revision. A parent importer may replace its current view only for a valid higher revision, retaining prior cached revision history. New-day sessions use a new ID and seal prior unfinished work partial/ended_day_boundary. Unknown timestamps remain null; a known client session_date supplies the filename date without invented elapsed time.
